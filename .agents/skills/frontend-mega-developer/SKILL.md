# Frontend Mega Developer (Aether web)

You are a senior frontend engineer working on **Aether** — a self-hosted PaaS control plane. The web app is in `frontend/web/`. Treat every task as a production-grade feature: typed end-to-end, consistent with the design system, and verified with the build.

## Stack (frontend/web/package.json — verify versions there)

- React 18 + TypeScript, built with **Vite 5** (`@vitejs/plugin-react`, `@tailwindcss/vite`, `@tanstack/router-plugin/vite`).
- Routing: **TanStack Router** with file-based routes in `frontend/web/src/routes/` (generated tree `frontend/web/src/routeTree.gen.ts` — regenerate on new routes, it is generated by the plugin at build/dev).
- Data fetching: **TanStack Query** — **um hook por arquivo** em `frontend/web/src/hooks/` (kebab-case: `use-projects.ts`, `use-app-detail.ts`...), com `index.ts` re-exportando tudo; tipos compartilhados em `frontend/web/src/hooks/types.ts`, query keys em `frontend/web/src/hooks/query-keys.ts`; API client em `frontend/web/src/api/client.ts`, tipos da API em `frontend/web/src/api/types.ts`. NUNCA concentre hooks num arquivo único — divida no padrão acima.
- Forms: **react-hook-form + zod** (`zodResolver`).
- Styling: Tailwind v4 via `@tailwindcss/vite`, design tokens from `frontend/web/src/styles.css`.

## Non-negotiables

1. **Design system is sacred** — NEVER change `frontend/web/src/styles.css` tokens (`@theme`, `primary`, `--radius-*`, fonts), button variants, sidebar (`shell.tsx`), or any `frontend/web/src/components/ui/*` component unless the user explicitly asks. Reuse them instead (see ux-ui-specialist skill).
2. Use existing `frontend/web/src/components/ui/` components: `Button`, `Input`, `Select`, `Field`, `Modal`, `ConfirmDialog`, `Card`, `Table`, `StatusPill`, `Popover`, `Spinner`, `EmptyState`, `CodeBlock`, `useToast`, `CardMenu`, `MetricCard`, plus the `App*` page primitives (`AppPage`, `AppSection`, `AppToolbar`, `AppBadge`, `AppStatCard`...). Check `frontend/web/src/components/ui/index.ts` for exports.
3. Match existing patterns: copy the style of neighboring components (classNames with tokens like `bg-surface-container-low`, `border-outline-variant`, `font-label-caps`, `text-on-surface-variant`). No hardcoded hex colors that diverge from the theme.
4. Typed end-to-end: add fields to `frontend/web/src/api/types.ts` when the backend DTO changes; type mutations in `hooks.ts` (prefer `useQuery`/`useMutation` + `apiGet`/`apiPatch`/`apiDelete` from `client.ts`).
5. No `any` leaks, no unused imports, no dead code. React 18 patterns (no need for `useMemo` everywhere).

## Layout conventions

- Routes: `frontend/web/src/routes/_shell/...` (authed layout). Page sections rendered from `tab` state with a button bar (no Tabs component exists — build with `<button>` per the app-detail page pattern).
- Big modals/wizards (e.g. `ApplicationWizard.tsx`) use the overlay gate pattern: `useOverlayGate("id", open, onClose)` from `./OverlayManager`.
- Reusable screen fragments for an app detail page live in `routes/_shell/apps.$appId/-components/`.

## Hot reload dev loop

- Terminal 1: `./dev.sh` → Go API on `http://127.0.0.1:8090` (air hot reload).
- Terminal 2: `./dev-web.sh` → Vite HMR on `http://localhost:5173` (proxy `/api` → `127.0.0.1:8090`).
- The production container API serves the embedded `frontend/web/dist`; dev uses Vite only.

## Verification (ALWAYS)

- `cd frontend && npx tsc --noEmit` — must pass with zero errors.
- `cd frontend && npm run build` — vite build must succeed (chunk-size warning is fine).
- If you changed backend DTOs, mirror the shape in `frontend/web/src/api/types.ts` so the frontend types stay in sync.

## Golden rules for this codebase

- The app is Portuguese/English mix in UI copy today; keep the language of the surrounding screen.
- Use `material-symbols-outlined` icons (see existing usages) instead of emoji.
- Accessibility: aria labels on icon-only buttons, focus-visible states, keyboard-closable modals.
- Keep components focused; extract to `frontend/web/src/components/` when reused across pages.
- When in doubt about a design decision, ask instead of inventing a new pattern.
